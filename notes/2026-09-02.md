# 2026-09-02:WKWebView 圖片偵測骨架(第一輪風險驗證,vault session 落地)

## 背景

Cyril 在 vault 端(另一個 Jarvis session)討論「像看網漫一樣即時翻譯」的體驗,查證後發現這就是本專案 README 一直排在「下一步(這次不做)」的 WKWebView 整合。vault 端規劃了完整整合的架構,但明確標出兩個未驗證、可能讓整條路線不可行的假設,建議先花一輪裝機驗證這兩點,再投入完整整合。這輪的工作就是把「第一輪風險驗證」的程式碼落地。

## 兩個要驗證的假設

1. 原生端 `URLSession` 帶 cookie+Referer 下載網頁圖片,抓不抓得到真的圖(很多站靠這個防盜鏈)
2. JS 偵測到的圖片網址是不是已經是 lazy-load 換好的真實網址,不是 `data-src` 占位字串

## 這輪新增的檔案

- `Sources/WebReader/PageBridge.swift`:注入用的 JS(字串常數,不是資源檔——避免 XcodeGen 對 `.js` 資源檔處理方式的不確定性)。`IntersectionObserver` 提前 2 個螢幕高度偵測 + `MutationObserver` 盯屬性變化(lazy-load)與節點新增(無限捲動動態插入圖片)
- `Sources/WebReader/MangaWebView.swift`:`UIViewRepresentable` 包 `WKWebView`,`WKUserScript` 掛在 config 上換頁自動重新注入
- `Sources/WebReader/TranslationRequestCoordinator.swift`:`WKScriptMessageHandler` 收圖片網址 → 同步 cookie(`HTTPCookie.requestHeaderFields`)+ Referer 下載 → 結果存進 `@Published probes` 給畫面顯示。含 `WeakScriptMessageHandler` 避免 `WKUserContentController.add(_:name:)` 造成的強引用循環
- `Sources/WebReader/MangaReaderView.swift`:網址列 + WebView + 除錯清單(偵測到/下載中/成功 bytes+尺寸/失敗原因)
- `ImgTranslateApp.swift`:改成 `TabView`,「閱讀」(新)+「引擎測試」(原本的 `ContentView`)並存
- `project.yml`:`dependencies` 加 `sdk: WebKit.framework`

## 刻意沒做的事

- 沒接翻譯 pipeline(`TextRecognizer`/`VLMTranslationEngine` 完全沒被這輪程式碼呼叫)
- 沒做疊字回填 DOM(`imgTranslateApplyOverlay` 之類的注入函式還沒寫)
- 沒做序列化處理佇列(這輪還沒有東西需要排隊,只有下載+解碼)
- 沒動 ATS(`Info.plist` 的 `NSAppTransportSecurity`)——如果裝機測試發現 HTTP 網站載入失敗,才需要考慮加例外,不要在還不知道要不要的情況下先放寬安全設定

## 這輪還沒裝機驗證,下次測試要看

1. 開一個 Cyril 實際會看的漫畫網址,捲動頁面,「閱讀」分頁下方除錯清單有沒有陸續列出圖片
2. 每筆有沒有從 🔍 變成 ✅(bytes+尺寸)——出現 ❌ 記錄是 HTTP 幾號還是「不是可解碼的圖片」
3. 如果整批失敗,先在系統 Safari 開同一個網址確認圖片本身載得出來,排除單純網址失效

任何一點不成立,就要回頭跟 Cyril 討論退回「手動截圖丟進 App」的半自動模式,不要硬做下去。過關才進下一輪(接翻譯 pipeline、疊字回填、序列化佇列)。
